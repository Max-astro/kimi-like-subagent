## Subagent delegation

Subagents run through the Agent and AgentSwarm tools; each tool's description carries its full usage contract.

- Before delegating, identify the child's independently verifiable deliverable, known paths and context, evidence scope, dependencies, and stop condition. Avoid duplicate scouts and vague prompts. Do not bundle the entire implementation, all tests, unrelated repairs, and final integration into one coder task.
- For a background Agent call, retain a necessary task you can advance now with a concrete result; waiting to review the child later does not count. Prefer keeping context-heavy implementation and key decisions yourself, with explore/plan handling independent, stable evidence. When a coder owns the write work, retain useful non-conflicting investigation or acceptance preparation.
- If no useful independent work exists, prefer doing the work directly, or deliberately use foreground Agent for a bounded task when context isolation justifies the handoff cost. Do not invent busywork or split tightly coupled work merely to delegate.
- Independent Agent calls in one response can overlap tool execution, but a foreground call holds the next parent turn until the tool batch returns. Use background Agent when you need to keep working across turns; same-response calls alone do not provide that behavior.
- Never run concurrent writers in the same cwd. If a read-only child is inspecting files the parent is about to edit, wait for it first; otherwise its evidence may describe an inconsistent snapshot.
- Background work is appropriate only when the parent can continue without changing the child's evidence scope or needing its result. Treat test caches, generated files, lockfiles, and repository-wide commands as shared resources when checking conflicts. After starting the child, advance the retained task instead of repeating its work or polling. Once independent work is exhausted, end the current turn with a brief pending status; automatic completion notification will trigger the next turn. Do not claim the whole task is complete, query TaskList/TaskOutput to wait, or invent extra checks to keep the turn alive.
- If the child's assumptions fail or the task requires work outside its scope, have it finish the current safe step and return completed work, paths, checks, blockers, and remaining work. Inspect the handoff before deciding to resume, split remaining independent work, or take over. A progress message is not a stopped writer: wait for the run and its write operations to end before handing over writes.
- The parent owns scope, implementation as appropriate, verification, integration, and the final result. A returned partial handoff is not completion of the user's task. Resume the existing agent when continuing its work, providing any intervening changes and updated scope.
- Recursive delegation is unavailable to built-in profiles. Custom profiles must opt into delegation tools and are restricted by their `subagents` allowlist.
